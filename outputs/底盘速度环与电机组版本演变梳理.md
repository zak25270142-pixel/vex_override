## 一、先给结论

1. 当前结构已经形成清楚的三层边界：
   - `MotorGroup`：采样、前馈/PID 基础计算、压摆执行、逐台电压映射；
   - `ChassisMotorGroup`：底盘单侧六态机、积分策略、状态对应的压摆策略；
   - `Chassis`：左右两侧的速度指令同比例缩回和电压同比例限幅。
2. 10 月 25 日的 `77613fa` 不是普通“抽类”，而是一次**控制量纲和责任边界同时变化**的重构：归一输出 `[-1,1]` 改成可调电压 `V`，`MyMotorGroup` 拆为 `MotorGroup + ChassisMotorGroup`，左右协调从联合层收回 `Chassis`。
3. 当前未提交改动是第二阶段重构：把 `calc_output()` 并入 `refresh()`，把 `output` 拆成 `output_raw/output_applied`，压摆从“逐电机电压”改到“组级可调电压”。这部分方向正确，尤其解决了不同 `volt_factor` 在爬坡阶段破坏比例的问题。
4. 目前默认构造的 `kp=ki=kd=0`，所以**未在线调参时并不是闭环 PID，而是纯前馈 + 状态机/压摆/限幅**。
5. 当前最值得先处理的不是继续拆类，而是三处口径断裂：
   - `pre_a` 在状态机读取前已经被覆盖，所谓“连续两拍低加速度”实际上退化为单拍；
   - 10 月 25 日量纲重构后，前馈标定脚本和多份文档仍按旧归一口径，重新标定会直接产出错误量纲；
   - 当前工作区取消 `output_raw` 的 ±12V 预夹幅，保留了控制器请求比例，但会让一侧虚高请求大幅压低另一侧，代码中也明确标为“未决”。

## 四、当前公式与字段语义

### 4.1 目标、采样和 PID

```text
now_v      = motors[0].velocity(pct)
now_a      = (now_v - pre_v) / dt_s
error      = target - now_v
derivative = (error - previous_error) / dt_s
output_raw = feedforward + kp·error + ki·integral + kd·derivative
```

- 速度反馈只取组内 0 号电机，不取组平均。
- `dt_s` 被夹在 `[1ms, 20ms]`。
- `kp/ki/kd` 单位分别为 `V/pct`、`V/(pct·s)`、`V·s/pct`。
- 左右组默认构造参数均为 `0,0,0`：`src/robot_and_control.cpp:55-62`。

### 4.2 摩擦垫与前馈

```text
base_volt = dynamic_deadzone
          + (static_deadzone - dynamic_deadzone) · exp(-|target|/3)
          + base_bias

feedforward = kf_at(target)       // 当前表覆盖 -100..100，y 已是 V
headroom    = 12 - base_volt - max(volt_min_i)
```

当前实值：

| 侧 | static | dynamic | max volt_min | 高速 headroom（约） |
|---|---:|---:|---:|---:|
| 左 | 1.01V | 0.80V | 0.597V | 10.603V |
| 右 | 1.04V | 0.80V | 0.542V | 10.658V |

### 4.3 两级比例缩回

1. `Chassis::output()`：速度目标层，任一侧超过本侧 `max_speed`，左右同比例缩回；记录 `spd_scale`。
2. `Chassis::speed_tick()`：电压层，任一运行侧 `|output_raw| > headroom`，左右同比例缩回；记录 `volt_scale`。

两者都保左右比例，不做单边削平。

### 4.4 当前逐台电压映射

```text
pad_i = target_sign · (base_volt + volt_min_i)
V_i   = pad_i + output_applied · volt_factor_i
```

`headroom` 的成立前提是 `volt_factor_i <= 1`。当前六台均满足；若在线把 factor 调到大于 1，最终单台电压仍可能越过 12V，由 SDK 自己截断，组内比例随即失真。

### 4.5 压摆策略

当前工作区把压摆锚点从“每台上次电压”改为“组级上次可调电压 `output_applied`”：

| 状态 | 幅值增大 `slew_rise` | 幅值减小 `slew_fall` |
|---|---:|---:|
| Transit / Track / Stable | 25 V/s | 200 V/s |
| Recover | ∞ | ∞ |
| Stall | 200 V/s | 25 V/s |
| Stopped | 不调用 `apply_output()` | 不调用 |

这是本轮重构中最有价值的一项：旧版逐台限速以各台 `volt_output` 为锚，`volt_factor` 大的电机会更早到位；新版先限制组级可调量，再统一乘 factor，爬坡全过程保持组内比例。

## 五、六态机细节

| 状态 | 含义 | 主要行为 |
|---|---|---|
| Stopped | 硬刹后环休眠 | 继续采样，但 `output_raw=0`，不下发闭环电压 |
| Transit | 起步/换向/目标大跳 | I 冻结，常规慢增压快撤压 |
| Track | 正常跟踪 | I 正常工作 |
| Stable | 小误差稳定 | 新增积分乘 `i_stable_k=0.5` |
| Recover | 被外力带偏但仍在动 | 两方向压摆全放开 |
| Stall | 给满且低速持续 100ms | 顶住快、松劲慢 |

主要转移：

- `Stopped → Track`：新目标非零且 `|target| < 3pct`。
- `Stopped → Transit`：其余非零起步。
- 任意活动态遇到 `|target-old_target| > 12pct`：进 Transit，但当前版本不清积分。
- 活动方向反转：进 Transit。
- `Transit → Track`：`|error| <= 8pct`；或冻结 20ms 后连续低加速度。
- `Track → Stable`：`|error| <= 2pct`。
- `Stable → Track`：`|error| > 3pct`。
- `Recover` 进入：非 Transit、目标与加速度反向，且 `|a|>200`；或者已给满且 `|a|>50`。
- `Recover → Transit`：`|error|<=8` 且不再给满。
- `Stall` 进入：非 Transit，给满且 `|now_v|<=8pct` 持续 100ms。
- `Stall → Transit`：轮速恢复，或目标归零。

## 七、确定存在的口径断裂与风险

### P0：前馈标定链仍是旧归一口径

这是目前最明确、后果也最大的断裂。

当前固件口径：

```text
V_i = sign·(friction + volt_min_i) + output_V·factor_i
```

因此从开环稳态电压反解当前前馈表，应是：

```text
output_V = (|V_need| - friction - volt_min_i) / factor_i
```

但 `backend/scripts/04-前馈表/cal_kf_table.py:15-27, 439-479` 仍按旧版计算：

```text
output_norm = (|V_need| - base) / ((volt_max-base)·factor)
```

并且仍把 y 画成“归一输出”。如果现在直接运行并把结果填回表，约 0~1 的旧量纲会被当成 V 使用，前馈会小一个数量级。

同类漂移还包括：

- `docs/代码功能说明/kf阻力前馈插值表.md` 仍写 `clamp ±1` 和旧反解式；
- `backend/scripts/04-前馈表/kf_open_sweep.py` 仍按旧 `volt_max/base/归一 output`；
- `backend/scripts/03-摩擦垫/car_vi_curve.py` 仍使用旧归一映射；
- `backend/scripts/02-电机组固有属性/cal_motor_intrinsic.py` 仍写 `MyMotor` 四字段顺序和 `volt_max`。

另外，`77613fa` 把旧表 y 直接乘 12：例如左 100pct 从 `0.9277` 变为 `11.1324V`。这只是单位缩放，不与旧物理映射严格等价：

```text
旧增量 = y_old · (12-base_i) · factor_i
新增量 = (12·y_old) · factor_i
```

新式比旧式多出 `y_old·base_i·factor_i`。以左侧 100pct、0 号电机估算：旧式约 10.57V；当前跨组 headroom 限幅后约 11.29V，差约 0.72V。是否合适必须用“纯前馈稳态速度 vs target”重新验收，不能仅凭换算认定等价。

### P0：`pre_a` 两拍去抖已退化为单拍

代码定义和文档都说 `pre_a` 是上一拍加速度，Transit→Track 要求连续两拍低加速度：

```cpp
fabsf(now_a) <= speed_stable && fabsf(pre_a) <= speed_stable
```

但当前顺序是：

```cpp
now_a = (now_v - pre_v) / dt_s;
pre_v = now_v;
pre_a = now_a;                 // 已覆盖
// 之后 ChassisMotorGroup::refresh() 才读取 pre_a
```

所以读取时恒有 `pre_a == now_a`，第二个条件没有增加任何信息。`git blame` 表明这套顺序在 `77613fa` 的拆层中形成：旧单函数版本是在状态机完成后才提交 `pre_a`，拆到基类后提交点被移到了状态机之前。

影响不是“所有 Recover 都必然误触发”，而是更具体的：Transit 可能提前一拍退出，随后同一轮的第二阶段判定不再受 `spin_state != Transit` 保护，Recover/Stall 的门就提前打开。

### P1：取消 ±12V 预夹幅后的跨侧耦合仍未定

当前工作区：

```text
s = max(1, |raw_L|/head_L, |raw_R|/head_R)
applied_L = raw_L/s
applied_R = raw_R/s
```

优点：严格保留控制器请求比例。

代价：若一侧 P/D 瞬间请求 30V、另一侧只请求 5V，按约 10.6V headroom 计算，另一侧只剩约 1.77V；旧版先夹 12V 时另一侧约 4.42V。新算法把“物理上根本做不到的 30V”也纳入左右话语权。

这不是可静态判定的 bug，代码已诚实标为未决。需要通过单侧受阻、另一侧自由的实车波形决定是否给 `output_raw` 增加“协调用请求上限”，而不是靠纯理论拍板。

### P1：启用 D 项时，起步首拍使用 1ms 的人为 dt

`set_target()` 从 Stopped 起步时先把 `last_time_us=now_us`，同拍 `refresh()` 的间隔不足 1ms，于是被夹成 1ms。

- D 项比正常 10ms 放大约 10 倍；
- 本拍压摆额度却缩成正常的 1/10；
- 即使压摆挡住本侧，巨大的 `output_raw` 仍先参与左右 `volt_scale`，可能把另一侧压低。

当前 `kd=0`，所以暂时无实际影响；一旦启用 D 项，这会从潜伏问题变成真实问题。

### P1：`volt_min_max` 构造时缓存，但 `volt_min` 可在线调

`volt_min_max` 只在构造函数计算一次；六个 `volt_min` 却挂在调参表上。在线修改某台 `volt_min` 后：

- 实际逐台垫底立即变化；
- `headroom` 仍用旧最大值；
- 抗饱和、giving_max、左右比例限幅三处同时使用过期天花板。

标定过程中这是会直接污染判断的状态不一致。

### P1：高目标下前馈本身已进入 giving_max 区域

当前高速 headroom 约为左 10.603V、右 10.658V；表尾分别为 11.1324V、10.9128V。约在左 95.4pct、右 97.8pct 后，单纯前馈就满足 `giving_max`。

因此高目标时 Recover 的加速度门槛会从 `recover_accel=200` 切到 `speed_stable=50`。这是现有判据的直接结果，不一定错误，但它把“前馈表尾标定”和“外力识别灵敏度”绑在了一起。前馈重新验收前，不应单独调 Recover 阈值。

### P2：0 目标时 headroom 偏保守

目标归零时 `target_sign=0`，实际下发不叠 `base_volt/volt_min`；但 `headroom` 仍减掉它们。若以后启用 P/D 做主动制动，可用电压实际接近 12V，限幅却只允许约 10.4V。当前默认 PID 全零，影响暂不显现。

### P2：非虚函数遮蔽有明确使用陷阱

`raw_groups[]` 的元素类型是 `MotorGroup*`。当前只通过它调用基类 `set_volt()`，安全；以后若从这张表调用 `set_target()/refresh()/stop()`，会静默绕过 `ChassisMotorGroup` 的六态语义。这个代价来自“无 virtual”的主动选择，应保持调用面严格受限。

### P2：文档和注释还有多处历史残留

- `docs/代码补充注释/01-MyMotorGroup-速度环与状态机.md` 仍断言 `pre_a/now_a` 是连续两拍，当前代码并非如此；
- 同文档仍写目标大跳需要 `Δtarget` 与 `target-pre_v` 两条件，当前代码只看 `Δtarget`；
- 多份材料仍使用 `drive()/my_spin()/MyMotorGroup/output clamp ±1` 等旧名和旧口径；
- `include/robot_upper.h`、`lift_bar.cpp` 当前未提交注释写成 `set_volt_raw`，实际方法名是 `set_volt`；
- `motor_speed_step.py` 仍写 5ms 周期，实际是 10ms。

## 八、我的判断：现在不该继续扩展抽象

我认可当前三层边界，不建议再引入“控制器对象”“输出管线对象”或恢复联合类。眼下问题不是抽象不足，而是一次量纲重构跨过了代码、标定脚本、文档和历史状态提交点，造成了同步断裂。

建议按以下顺序收口：

1. **先修口径真源**：确定当前 V 量纲公式，更新前馈/摩擦/固有属性三类标定脚本和文档，再做纯前馈复测。
2. **恢复 `pre_a` 的真实上一拍语义**：只决定提交时机，不要借机再改状态阈值。
3. **为 D 项起步首拍定口径**：决定是保留真实 10ms 采样间隔，还是起步首拍明确禁用 D；不要让 1ms 既参与 D 又参与跨侧限幅。
4. **记录 `spd_scale/volt_scale/output_raw/output_applied`**：这四个当前都没有完整监控出口，实车无法直接判断到底是目标层、比例限幅还是压摆在削。
5. **最后再决定 raw 请求是否预夹**：用“单侧顶住 + 双侧正常 + 高速减速”三组波形做判断。
6. `feature/big_quan` 暂不合并；等小车 V 量纲与脚本口径稳定后，再迁移四轮协同算法。
