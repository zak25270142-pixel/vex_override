# 底盘速度环：原版（抽离前）与当前版本的优缺点及改进措施

> 对比口径
>
> - **原版**：`master` / `feature/old_car` 的 `fd00f31 缓停推广`（2026-10-18 22:54），抽离前的单类 `MyMotorGroup` + 归一输出版本。
> - **当前版**：`feature/small_car` HEAD `77613fa`（2026-10-25）**加当前未提交工作区**（第二阶段重构）。
> - 本报告只分析设计与行为，不改代码；所有改进措施给出候选形态与代价，等你确认后再动文件。

## 一、结构对照总表

| 维度 | 原版 `fd00f31` | 当前版 `77613fa + 工作区` |
|---|---|---|
| 类结构 | 单类 `MyMotorGroup`（含六态机） | `MotorGroup`（通用）+ `ChassisMotorGroup`（底盘派生） |
| 文件 | `chassis.h` 装 `MyMotor`+`MyMotorGroup`+`Chassis`；`my_motor_group.cpp` / `chassis.cpp` | 新增 `my_motor_group.h`；`chassis.h` 装派生类 + `Chassis` |
| 每拍入口 | `drive(target)` + `my_spin()`（一个函数走完） | `set_target()` → `refresh()` → `apply_output()` 三段 |
| 控制量量纲 | 归一 `[-1,1]` | 可调电压 V |
| 逐台映射 | `sign·(friction+volt_min_i) + o·(volt_max_i−base_i)·factor_i` | `sign·(base_volt+volt_min_i) + output_applied·factor_i` |
| 每台上限字段 | `MyMotor::volt_max`（逐台，实测全填 12） | 已删除，改组级 `headroom` |
| 余量真源 | 无；抗饱和 ±1、Stall 0.99、映射处 `(volt_max_i−base_i)` 三处各算 | `headroom = 12 − base_volt − max(volt_min_i)`，三处共用 |
| 压摆锚点 | 每台 `volt_output`，逐台限速 | 组级 `output_applied`，先限可调量再乘 factor |
| 跨侧协调 | 只有目标层缩回（`left/right_max_speed`）；电压层无 | 目标层 `spd_scale` + 电压层 `volt_scale` 两级同比例缩回 |
| 前馈表 | 仅正半轴 `|target|`，y 为归一口径 | 覆盖 −100..100，y 直接是 V |
| 默认增益 | `kp=0.006`（归一/pct）、`ki=0.08`（归一/(pct·s)）、`kd=0` | `kp=ki=kd=0`（纯前馈） |
| 硬件形态 | 旧车，左右各 4 台（PORT6-9 / 17-20） | 小车，左右各 3 台（PORT1-3 / 5-7） |
| 停车语义 | 外部直读 `spin_state == Stopped` | 封装为 `is_stopped()` |
| 代码规模 | 3 文件共 670 行 | 4 文件共 907 行（+35%） |

## 二、原版优点

### 1. 一拍一条直线，读代码即执行顺序

`my_spin()`（`fd00f31:src/class_and_tool/my_motor_group.cpp:68-205`）从头到尾就是一拍的完整过程：算 dt → 采样 → 状态机① → 摩擦/前馈/PID → 夹幅 → 状态机② → 电压映射 + 压摆 → 更新历史。新读者不需要跨文件拼时序，也不需要知道“先调谁后调谁”。

### 2. 没有跨函数的调用顺序契约

原版只有两个入口，且 `drive()` 与 `my_spin()` 的相对顺序即使颠倒也只是晚一拍生效，不会算错。当前版则必须保证 `set_target → refresh → apply_output` 同拍按序，因为压摆额度用本拍 `dt_s`、状态机要用本拍 `output_raw`——这条契约目前只由注释维持。

### 3. 历史量提交在函数末尾，天然是“上一拍”

```cpp
// 原版 my_spin 末尾（:201-205）
// 更新历史
previous_error = error;
pre_v = speed;
pre_a = now_a;
```

状态机在本函数前段读 `pre_v/pre_a`，提交在末尾，两者必然属于不同拍。当前版把提交点移进基类 `refresh()`，而状态机在 `refresh()` **之后**才读，于是 `pre_a` 恒等于 `now_a`（详见第五节）。

### 4. 中间量是局部 `const`，没有“陈旧字段”风险

`error / derivative / friction / p_output / d_output / output` 全是 `my_spin()` 内的局部变量。不存在“这个字段是谁写的、是哪一拍写的”这类问题。当前版把它们提升为跨函数字段（`error/derivative/base_volt/feedforward/headroom/output_raw`），可读性换来的是生命周期复杂度。

### 5. 归一输出与硬件解耦，参数跨车可迁移

`kp/ki` 是相对量（归一/pct），换电池电压、换电机、换车轮直径后数量级不变；上位机与调参表看到的是 0~1，不需要知道母线电压。代价是物理含义不直观（见缺点）。

### 6. 抗饱和与顶格判据极简，只有一个常量

```cpp
if (output > 1) output = 1; else if (output < -1) output = -1;   // :116-118
const bool giving_max = fabsf(output) >= stall_output;            // :122，stall_output=0.99
```

夹幅上限、抗饱和天花板、Stall 顶格判据都是同一个 ±1，不存在“两个天花板必须是同一个数”的一致性要求。当前版引入 `headroom` 后，抗饱和、giving_max、跨侧限幅三处必须共用它，多了一处必须维护的不变量。

### 7. 每台电机可以有自己的电压上限（能力上存在）

`MyMotor::volt_max` 让逐台可调区间 `(volt_max_i − base_i)` 可以不同，理论上能表达“某台电机不允许满压”的结构限幅。当前版删掉了这个字段。

### 8. 状态机与 PID 同处一函数，判据能看到“夹幅后的真值”

原版状态机② 用的是已经夹到 ±1 的 `output`，判据与物理可发范围一致。当前版为了保比例改用未限幅的 `output_raw`，判据看到的是意图而非事实，这带来了“虚高请求是否该有话语权”的新争议。

### 9. 模块少、编译单元少、调参表短

没有额外头文件和类层次；监控系统只需要绑 `volt_output`、`spin_state` 等少数几个量。当前版多了一个头文件、一层继承、两组压摆字段和若干新字段。

### 10. 外部可直接读状态枚举

`robot_action.cpp:195-196` 直接比较 `chassis.left_motors.spin_state == MyMotorGroup::SpinState::Stopped`，不需要额外访问器——当然这也是耦合（见缺点 9）。

## 三、原版缺点

### 1. 一个类混了六件事，无法被其它机构复用

`MyMotorGroup` 同时负责：物理映射、六态机、PID、积分策略、压摆策略、逐台下发。升降杆想要“一组电机 + 速度环”但不需要六态机时，只能复制一份——事实上后来 `LiftMotorGroup`（`include/robot_upper.h`）就是另写一套，且仍用归一口径，两套量纲长期并存。

### 2. 归一输出把“真实电压余量”藏进了映射里

逐台可调区间在下发处才算：

```cpp
const float base_voltage = friction + motors[i].volt_min;             // :173
const float controllable_voltage = motors[i].volt_max - base_voltage;  // :174
```

而抗饱和用 ±1、Stall 用 0.99。当 `volt_factor_i` 不同时，`output=1` 对每台意味着不同电压（`base + (12−base)·factor_i`），有的电机先饱和、有的还没到——**归一饱和 ≠ 物理饱和**。这是“两个天花板不是同一个数”的早期形态。

### 3. 完全没有跨侧电压协调

```cpp
void Chassis::speed_tick()          // fd00f31:src/class_and_tool/chassis.cpp:182-187
{
    left_motors.my_spin();
    right_motors.my_spin();
}
```

只有 `output()` 里的目标层缩回（:172-180），电压层各跑各的。一侧被顶住顶到 12V、另一侧也想要 12V 时，没有任何机制让出电压，左右出力比被母线能力扭曲 → 直行跑偏、转向半径漂移。

### 4. 压摆以每台电压为锚，破坏组内 factor 比例

```cpp
const float volt_output = motors[i].volt_output;   // :176，逐台各自的锚
```

`factor` 大的电机每拍能走的绝对电压更多，会先到位；爬坡全程组内出力比例被拉歪。左组 factor 0.933/1.000/0.924 时，斜坡期间差可达 8%。

### 5. 前馈一大就长期“假饱和”，I 项被误冻

抗饱和候选是 `feedforward + p + ki·(integral+Δ) + d`，天花板是 ±1。前馈表稍大，`candidate` 就长期 ≥1，I 项永远补不进去，低速静差只能靠前馈表精度硬扛。文档承认这是刻意设计（I 只补 ff+p 补不上的部分），但代价是前馈误差无法被闭环修正。

### 6. 输出量纲不物理，标定与调试都要换算

- 上位机看到的 `output` 是 0~1，要判断“还能给多少电压”必须心算 `base + o·(12−base)·factor`；
- 前馈表占位值 `ff(100)=1.0` 在 `factor<1` 的机组上并不等于满压，文档自己写着“表尾不必 ff(100)≈1.0”——这正是归一量纲造成的认知负担；
- `kd` 的单位注释写成“秒/pct”（:107），与 kp/ki 的归一口径混用，单位体系本身不自治。

### 7. 前馈表只覆盖正半轴，无法表达非对称

```cpp
feedforward = target_sign * kf_at(fabs_target);   // :100
```

正反向被迫对称，机构的固有不对称（脚轮、传动、坡度）无处安放，只能靠 I 项兜。

### 8. 单函数过长，改一个判据要通读 140 行

`my_spin()` 里状态机、PID、映射、压摆交织。任何一处小改（例如给 Recover 加一个条件）都要在长函数里定位，且容易误伤相邻逻辑——`281475f` 那次 `&&`/`||` 优先级 bug 就出在这种密集布尔表达式里。

### 9. 外部直读枚举造成耦合

`robot_action.cpp` 需要知道 `MyMotorGroup::SpinState` 这个类型与 `Stopped` 成员；底盘内部状态机变成外部可见的实现细节。当前版用 `is_stopped()` 收敛了这一点。

### 10. 每台 `volt_max` 能力闲置，反而制造调参噪音

八台全部填 12.0（`fd00f31:src/robot_and_control.cpp:33-44`），`L_vmax0..3 / R_vmax0..3` 八个调参项（`LCD_menu.cpp:41-48`）全是常量，既占调参表又误导“这里可以调”。当前版删除是正确的减法。

### 11. 没有“请求 vs 已下发”的分离

`output` 是局部变量，映射后只剩每台 `volt_output`。现场发现“电压没给够”时，无法区分是控制器没要、被限幅、还是被压摆挡住——`speed_loop_probe` 只能靠 `L0_Vcmd` 反推。

### 12. 命名不表意

`drive()`（改目标）、`my_spin()`（跑一拍）、`output_deadzone`（其实是目标死区）——三个名字都不能从字面推出作用，是历史包袱。

## 四、当前版优点

1. **三层边界清楚**：`MotorGroup` 只算量与执行、不判断；`ChassisMotorGroup` 只判断与给策略；`Chassis` 只做跨侧协调。升降杆可以用 `MotorGroup` 而不被六态机污染。
2. **电压量纲物理直观**：`kp[V/pct] / ki[V/(pct·s)] / kd[V·s/pct]` 单位自治；前馈表 y 直接是 V；监控读数就是电压，不用换算。
3. **`headroom` 成为单一真源**：抗饱和、giving_max、跨侧限幅三处共用同一个数，消除了“两个天花板”类错误（当前代码已把这条写成显式注释）。
4. **组级压摆锚点 `output_applied`**：先限可调量、再乘 factor，组内出力比例在爬坡全程保持（左组 0.933/1.000/0.924 不再互相拉扯）。
5. **跨侧两级同比例缩回**：目标层 `spd_scale`、电压层 `volt_scale`，都保比例不削平；一侧顶住时另一侧按比例让出，避免整车被拽偏。
6. **单一采样点**：`MotorGroup::refresh()` 是唯一读编码器的地方，状态判据与控制律必然同源，杜绝“两个样本”。
7. **`output_raw` / `output_applied` 分离**：请求值与已下发值分开，限幅与压摆可归因（目前尚未挂监控，见第五节）。
8. **前馈表覆盖负半轴**：`kf_at(target)` 直接按带符号 target 查表，可表达非对称机构与正反向差异。
9. **Stopped 语义封装**：`is_stopped()` 取代外部直读枚举；停车组仍采样但不下发，开环直写电压天然不被覆盖，因此不需要任何“开环标志”。
10. **开环接口成组化**：`set_volt(const float*)` + `raw_groups[]`，命令从“单台编号”改成“组别 + 4 槽电压”，协议与语义都更整齐。
11. **设计理由入库**：压摆为什么要限速在可调量上、垫底为什么不进窗口、为什么 Stopped 不下发 0V，都有注释；未决项（请求是否预夹）也被诚实标注在 `chassis.cpp:400-404`。
12. **命名表意**：`set_target / refresh / apply_output / slew_rise / slew_fall / target_deadzone` 都能从字面推出作用。

## 五、当前版缺点

1. **隐式调用契约**：`set_target → refresh → apply_output` 必须同拍按序；漏调、错序、重复调都不会报错，只会产出慢一拍或错一拍的行为。基类只有注释约束。
2. **状态从局部量变成跨函数字段**：`error / derivative / base_volt / feedforward / headroom / output_raw` 都有了跨函数生命周期，陈旧值风险上升；`pre_a` 就是第一个实际踩到的（见下条）。
3. **`pre_a` 语义退化（P0）**：`refresh()` 里 `pre_a = now_a` 先提交，状态机后读，恒等；“连续两拍低加速度”退化为单拍判据，Transit 可能提前一拍退出，Recover/Stall 的 `spin_state != Transit` 保护随之提前失效。
4. **`volt_min_max` 构造期缓存 vs `volt_min` 在线可调**：在线改某台 `volt_min` 后，实际垫底变了而 `headroom` 没变，抗饱和、giving_max、跨侧限幅三处同时用过期天花板。
5. **`headroom` 在 `target=0` 时偏保守**：此时 `target_sign=0`、实际不下发垫底，可用电压接近 12V，但 `headroom` 仍减掉 `base_volt+volt_min_max`（约 10.4V）。当前 PID 全零，暂不显现。
6. **取消 ±12V 预夹幅后的跨侧耦合未定**：一侧 P/D 瞬间请求 30V、另一侧 5V 时，另一侧只剩约 1.77V（旧口径约 4.42V）。保住了比例，但让“物理做不到的请求”参与了话语权。
7. **起步首拍 `dt` 被夹成 1ms（潜伏）**：`set_target` 从 Stopped 起步时重置 `last_time_us`，同拍 `refresh` 间隔不足 1ms。启用 D 后该项放大约 10 倍，且会先参与跨侧 `volt_scale`。当前 `kd=0` 无影响。
8. **非虚遮蔽的静默风险**：`raw_groups[]` 是 `MotorGroup*`；一旦有人从这张表调 `set_target()/refresh()/stop()`，会静默跳过六态机。这是“去掉 virtual”换来的代价。
9. **量纲重构后标定链未同步（P0）**：`cal_kf_table.py` 仍按 `y=(|V|−base)/((volt_max−base)·factor)` 反解归一口径；`kf_open_sweep.py`、`car_vi_curve.py`、`cal_motor_intrinsic.py` 以及 `kf阻力前馈插值表.md` 同样停留在旧世界。现在跑标定会把 0~1 的旧量纲当成 V 填表。
10. **`y×12` 换算不等价**：旧增量 `y·(12−base_i)·factor_i`，新增量 `12y·factor_i`，新式多出 `y·base_i·factor_i`。左 100pct 估算旧约 10.57V、新约 11.29V，差约 0.72V；且已超过 headroom（10.603V）。
11. **监控出口不足**：`spd_scale / volt_scale / output_raw / output_applied` 四个都没挂监控表，现场只能从 `L_head/R_head` 反推是谁在削。
12. **高目标前馈本身就满足 giving_max**：左约 95.4pct、右约 97.8pct 以上，纯前馈已 ≥0.99·headroom，Recover 的加速度门槛从 200 降到 50。前馈表尾标定与外力识别灵敏度被绑在一起。
13. **注释与代码出现漂移**：`docs/代码补充注释/01` 仍写 `pre_a/now_a` 是连续两拍、大跳要双条件；`robot_upper.h:163` 与 `lift_bar.cpp:262` 写成 `set_volt_raw`（实际是 `set_volt`）；`LCD_menu.cpp:75` 仍提升降杆的 `vmax`（字段已删）；`motor_speed_step.py` 仍写 5ms。
14. **代码规模与理解成本上升**：4 文件 907 行（原 3 文件 670 行），新读者要跨 4 个文件才能拼出一拍；收益真实但并非免费。
15. **工作区改动未拆分提交**：底盘重构与微信小程序改动混在同一次未提交变更里（19 个文件），回滚与 bisect 都会被污染。

## 六、净判断：哪些是真改进，哪些是等价迁移，哪些是新风险

**真改进（行为变好）**

- 跨侧电压比例限幅：原版完全没有，这是实打实的跑偏修复。
- 压摆改到组级可调量：修掉 factor 差异导致的爬坡期比例失真。
- `headroom` 统一三处天花板：消除归一口径下的“假饱和”隐患。
- 单一采样点 + 单一真源的前置量：消除两个样本 / 两个数。
- Stopped 门控取代开环标志、开环接口成组化、前馈表覆盖负半轴、命名表意化。

**等价迁移（结构变，行为基本不变）**

- `MyMotorGroup → MotorGroup + ChassisMotorGroup` 的拆类本身；
- 局部量 → 字段（`error/derivative/feedforward` 等）；
- `drive → set_target`、`my_spin → calc_output → refresh` 改名；
- `left/right_max_speed → MotorGroup::max_speed`；
- 删除 `virtual` 改同名遮蔽（当前调用面下行为一致）。

**新引入的风险（原版没有）**

- 隐式调用顺序契约；
- `pre_a` 退化（原版提交在末尾，天然正确）；
- `volt_min_max` 缓存过期（原版逐台现算 `(volt_max_i−base_i)`，不存在此问题）；
- 起步首拍 1ms dt 参与 D 与跨侧限幅（原版也有 1ms dt，但 D 不参与跨侧限幅，且没有跨侧限幅这一层）；
- 未限幅请求参与跨侧比例（原版先夹 ±1 再映射，天然有限）；
- 非虚遮蔽的静默绕过（原版单类，无此问题）；
- 标定链与文档滞后（原版脚本与代码口径一致）。

## 七、改进措施（候选形态 + 代价，待确认后再动文件）

### P0-1 前馈标定链改到 V 口径

- 问题：脚本仍按归一口径反解，重新标定会填错量纲。
- 候选 A（推荐）：`cal_kf_table.py` 反解式改为 `y = (|V_need| − friction(v) − volt_min_i) / volt_factor_i`（参数取 `motors[0]`），图注改“前馈输出（V）”；`kf_open_sweep.py`、`car_vi_curve.py` 同步；`kf阻力前馈插值表.md` 改公式与 clamp 描述；`cal_motor_intrinsic.py` 字段顺序注释改 3 字段。
- 候选 B：保留脚本，只在脚本顶部加醒目警告“仅适用于 77613fa 之前”。
- 代价：A 约改 4 个文件 40~80 行 + 1 篇文档；B 近乎零成本但下次仍会踩。
- 推荐：A。属“口径真源”修复，不应拖。
- 需确认：`volt_min_i` 取 `motors[0]` 还是组内均值（当前代码用 `max(volt_min_i)` 算 headroom，反解与限幅是否要同源）。

### P0-2 恢复 `pre_a` 的“上一拍”语义

- 问题：`refresh()` 内先提交 `pre_a`、状态机后读，恒等。
- 候选 A（推荐）：基类 `refresh()` 开头先把旧值转存到专用字段，例如新增 `accel_prev`，序列改为 `accel_prev = pre_a; now_a = (now_v − pre_v)/dt_s; pre_v = now_v; pre_a = now_a;`，状态机读 `accel_prev`。基类自洽，派生无感，约 3 行。
- 候选 B：把 `pre_a` 提交移到 `ChassisMotorGroup::refresh()` 末尾（含 Stopped 早退分支也要提交）。改动更小，但基类单独使用时语义不完整。
- 候选 C：状态机只读 `now_a`，删掉 `pre_a` 判据，正视“单拍”事实并把去抖需求交给别处（例如 Transit 冻结窗延长到 30ms）。
- 代价：A/B 各 3~6 行，需同步监控项“左加速度(慢1拍)”（应绑哪个要明确）；C 改判据语义，会影响 Recover/Transit 灵敏度。
- 推荐：A（保住原设计意图，改动最小）。
- 需确认：监控项 `L_a/R_a` 的命名与绑定位。

### P1-1 起步首拍 dt 口径

- 问题：`set_target` 从 Stopped 起步重置 `last_time_us`，同拍 dt 被夹 1ms，启用 D 后放大 10 倍并参与跨侧限幅。
- 候选 A（推荐）：起步分支不再重置 `last_time_us`，让首拍 dt 取真实间隔（最多被夹到 20ms）。1 行改动。
- 候选 B：首拍强制 `dt_s = 0.010f`。简单但捏造数据。
- 候选 C：D 项单独使用“上一拍真实间隔”，不参与夹取。多一个字段。
- 代价：A 几乎为零；需实车确认起步头几拍电流/冲击无异常。
- 推荐：A。

### P1-2 `volt_min_max` 改为每拍现算

- 问题：构造期缓存，在线改 `volt_min` 后三处天花板过期。
- 候选 A（推荐）：在 `refresh()` 里每拍遍历求 max（3~4 台，开销可忽略）。
- 候选 B：保留缓存 + 提供 `recalc()`，在菜单改值时调用（现有菜单只绑指针，需要额外回调机制）。
- 代价：A 约 5 行、每拍多 3 次比较；B 需要改菜单框架。
- 推荐：A。
- 需确认：是否接受 `headroom` 在标定过程中随调参实时变化（我认为这正是想要的）。

### P1-3 跨侧限幅是否预夹请求

- 问题：未限幅请求参与比例，极端 P/D 下另一侧被过度压缩。
- 候选 A：维持现状（不夹），保意图比例。
- 候选 B：先夹 ±12 再算比例（回到旧行为）。
- 候选 C：夹到 `k × headroom`（如 3×），既限制虚构量又不完全抹掉比例意图。
- 候选 D：只对“超出部分”做软化（例如超出段按平方根压缩）。
- 代价：都只改 2~4 行，但没有实车数据无法判定优劣。
- 推荐：**先补监控再决定**。用三组波形判断：单侧顶住 / 双侧正常加速 / 高速松杆减速。
- 需确认：是否接受为验证临时挂监控项。

### P1-4 解除 `speed_stable` 一身三职 + 复核表尾

- 问题：`speed_stable` 同时是 Transit→Track 阈值、Recover 兜底门槛、Stall 门槛；且高目标前馈本身就满足 giving_max，把表尾标定与外力识别绑死。
- 候选 A（推荐）：给 Recover 兜底支单独一个参数（如 `recover_accel_given_max`），让 `speed_stable` 只管 Transit→Track。
- 候选 B：前馈复测后把表尾压到 headroom 以内（承认 ff(100) 不应超过余量，差额交给 P/I）。
- 代价：A 增加 1 字段 + 1 调参项；B 依赖 P0-1 完成后的复测结果。
- 推荐：先 B（复测自然收敛），再评估是否仍需 A。
- 需确认：B 会不会让高速段稳态转速掉下来（需要 P/I 接力）。
