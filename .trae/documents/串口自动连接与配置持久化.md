# 串口自动连接 + 配置持久化 实现方案

## Context（为什么做）

调试时用户需要反复给主控断电、上电、重新烧录固件。当前每轮都要：手动点「连接」→ 点「获取实参表」→ 重新配一遍订阅关系与曲线通道（追踪项、时间窗口、y 轴刻度）。

问题的技术根因有两个：

1. **无任何持久化**：全项目没有 localStorage/sessionStorage 代码。`channelTraces`、`channelCfg`、订阅态刷新即丢。
2. **订阅态没有独立存储**：订阅状态寄生在 `monitorMap[index].tag` 的位域里（`MONITOR_TAG_SUB=0x80` / `MONITOR_TAG_FAST=0x40`）。每次 `fetchMonitor()`（[globle.ts](file:///d:/work/vex/test1/frontend/src/stores/globle.ts#L493-L502)）会先 `clearMonitorData()` 把整表清空再拉目录，主控回传的目录里订阅位是默认值 —— 订阅信息必然丢失。
3. **无重连机制**：`handleUnexpectedDisconnect` 只上报 error，不重试；`preselect()` 只在启动时盲取 `ports[0]` 供手动连接。

目标：打开/刷新页面自动连上已授权串口；主控断电或拔线后每约 1.5s 静默重试直到连上；连上后自动恢复订阅关系与曲线配置。**首次授权仍需手动（Web Serial 限制，`requestPort()` 必须在用户手势里）。**

## 已确认的决策

| 项 | 决定 |
|---|---|
| 持久化键 | **按索引**（`monitorMap` 的 index）。用户确认接受"固件改动导致索引漂移则恢复错位"的风险 |
| 断开行为 | **持续重试**，间隔 1000~1500ms，直到连上或用户手动断开/关闭开关 |
| 自动连接开关 | 顶栏加复选框，**默认开启**，可随时关；首次无授权设备时自动跳过 |
| 持久化范围 | 连接相关（端口 VID/PID、自动连接开关、演示模式）+ 订阅关系 + 曲线通道配置 |
| 不持久化 | 调参草稿、当前分页、搜索关键词、`scopeDrawer`（浮层开合属瞬时态） |

## 改动清单

### 1. 新增 `frontend/src/services/persist.ts`（唯一新文件，约 50 行）

纯存储层，不含业务知识，避免与 globle.ts 循环依赖。单个 localStorage key `v5.prefs.v1`：

```ts
export interface Prefs {
  autoConnect: boolean      // 默认 true
  demo: boolean             // 默认 false
  port: { vid: number; pid: number } | null
  subs: Record<number, { sub: boolean; fast: boolean }>
  chart: {
    traces: number[][]      // 4 通道，每通道原始 index 列表
    cfg: { windowS: number; yAuto: boolean; yMin: number; yMax: number }[]
    focusCh: number | null
    bigView: boolean
  }
}
```

导出 `loadPrefs(): Partial<Prefs>`、`savePrefs(patch: Partial<Prefs>): void`（内部 `Object.assign` 合并 + 300ms 防抖写盘）、`prefs` 内存快照。`loadPrefs` 对读到的数据做边界校验（丢弃非数字/超范围的 windowS、`yMin>=yMax`、负 index、通道数不符的 traces），storage 是系统边界，需校验。

### 2. `frontend/src/services/webSerialTransport.ts`

- 新增 `identity: {vid,pid} | null` 字段，`pickPort()` 成功后从 `port.getInfo()` 记录。
- `preselect()` 改为：`getPorts()` 里优先按 `identity`（来自持久化）匹配 VID/PID，匹配不到回落 `ports[0]`；匹配到多个同 VID/PID 设备时仅取第一个并在状态里提示"检测到多个设备，请点选口手动指定"。
- **新增 `reacquire()`**：重试时重新 `navigator.serial.getPorts()` 解析端口对象（重插后 Chrome 通常复用同一 `SerialPort`，但不保证）；返回空列表时保留旧对象继续尝试。**静默循环里绝不调用 `requestPort()`**（需手势）。
- **把 `disconnect()` 的清理体抽成 `closeStreams()`（私有）**，`connect()` 开头无条件先调一次。清理顺序（每步 try/catch 吞异常，物理拔线后旧对象可能抛）：`keepReading=false` → `removeEventListener('disconnect')` → `reader.cancel()` → `await readTask` → `reader.releaseLock()` → `reader/readTask=null` → `writer.close()` → `writer.releaseLock()` → `writer=null` → 若 `port.readable||port.writable` 则 `port.close()`。**这是根治第二次 `open()` 抛 "already open / Failed to open" 的关键**。`disconnect()` 复用该函数并额外通知 SerialClient 停止重试。

### 3. `frontend/src/services/serialClient.ts`（重连状态机放这一层）

重连是"恢复用户意图"，不是物理收发，且 `transport` 实例会被 demo 切换、`pickPort()` 整体替换，放 `WebSerialTransport` 内会污染被 `MockTransport` 共用的接口。

新增字段：`wantConnected`（用户是否希望连接）、`autoConnect`、`retrying`（重入锁）、`retryTimer`、`lastForwarded`（去重相同状态文案）。

- `connect()` / `autoConnect()`：置 `wantConnected = true` 后尝试连接；`autoConnect()` 在 `!isPortReady()` 时直接跳过（无授权设备，不启动循环，仅提示"请点选口"）。
- `disconnect()` / `setDemoMode(true)`：置 `wantConnected = false`、清 `retryTimer`，**不触发重试**。
- **重试用递归 `setTimeout`（不是 `setInterval`）**，间隔 1500ms。`open()` 可能挂起，interval 会并发开同一口。
  - `attempt()` 以 `retrying` 做重入锁；取当前 `this.transport` 并校验 `instanceof WebSerialTransport`（不缓存实例）；`await t.reacquire()` → `await t.connect(baud)`；`finally` 里再判 `wantConnected && !connected && !demo` 才 `schedule()` —— 这一个条件同时覆盖"运行中断开重连"和"页面加载时设备还没插上"两种场景，无需区分主动/意外断开。
- **静默降级**：`open()` 抛 `SecurityError`/`NotAllowedError`（缺手势）→ 停止循环，上报 `idle` "设备已就绪，请点击连接"；其余错误（被 VEXcode/另一标签页占用等）→ 保持静默重试，UI 仍可手动点「连接」。
- **防刷屏**：`cb.onStatus` 里比对 `lastForwarded`，`state` 与 `message` 与上次完全相同时不再转发（重试期间"正在打开…"/"打开失败…"会重复几十次）。
- 端口身份持久化：`pickPort()` 成功后把 `{vid,pid}` 写入 `persist.savePrefs({ port })`；`init()` 时先读取并注入 transport 的 `identity`。

### 4. `frontend/src/stores/globle.ts`

- **新增持久订阅表** `desiredSubs = new Map<number, {sub,fast}>()`，在 `setSubscription()`（[L527](file:///d:/work/vex/test1/frontend/src/stores/globle.ts#L527-L540)）里同步维护 —— **包括 `sub=false` 的退订**（要与主控默认订阅位对抗）。发帧成功后写 `savePrefs({ subs })`。
- **恢复挂钩点：`handleEvent` 的 monitor 目录分支**（[L329-333](file:///d:/work/vex/test1/frontend/src/stores/globle.ts#L329-L333)）。理由：协议**没有"目录结束"标记**，逐项到达是唯一可用时机；且目录帧能到达本身就证明主控程序已就绪（避免冷启动时订阅帧发早了丢失）。每项目录到达时：若 `desiredSubs` 里有该项且 `restoredSubs` 集合里没有，则 `setSubscription(idx, sub, fast)` 并记入 `restoredSubs`（防止重复拉目录时重发）。`restoredSubs` 在断开时清空。
- **曲线配置恢复**：新增导出 `restorePrefs()`，把 `prefs.chart` 写回 `channelTraces` / `channelCfg` / `focusCh` / `bigView`，并做去重（`pickTrace` 同通道禁重复）、剔除非法 index —— 在组件挂载前调用，保证 `ScopeConfig`（`:key="scope-${focusCh}"`，草稿按挂载值初始化）拿到的是恢复后的值。恢复顺序：先写 `channelTraces`/`channelCfg`，最后设 `focusCh`/`bigView`（`watch(focusCh)` 会重置 `scopeDrawer`）。
- **曲线配置保存**：模块级注册 `watch([channelTraces, channelCfg, focusCh, bigView], ..., { deep: true })` → 防抖后 `savePrefs({ chart })`。ChartView 已有的 deep watch 会自动补帧，无需改图表代码。
- 新增导出 `autoConnect`（`ref`，默认 true）供顶栏绑定，改动即 `savePrefs({ autoConnect })`。

### 5. `frontend/src/main.ts` + `frontend/src/App.vue`

- [main.ts](file:///d:/work/vex/test1/frontend/src/main.ts)：`createApp` 之前调用 `restorePrefs()`（必须在任何组件挂载前完成曲线状态恢复）。
- [App.vue](file:///d:/work/vex/test1/frontend/src/App.vue#L39-L51) `onMounted` 里，`await serialClient.init()` 之后追加 `if (autoConnect.value && !demoMode.value) void serialClient.autoConnect(baud)`。`open()` 不需要用户手势（只有 `requestPort()` 需要），所以加载即连可行。`beforeunload` 的 `disconnect()` 保持不变（会释放端口，避免下次打开时口被占）。

### 6. `frontend/src/components/shell/AppHeader.vue`

"演示"复选框旁增加"自动连接"复选框（同样的 `.demo-switch` 样式类，保持视觉一致），绑定 `autoConnect`。演示开关与自动连接开关持久化后，顶栏"演示数据源"徽标已能明确显示当前处于哪种模式。

## 风险与限制（需如实告知，无法完全消除）

1. **首次必须手动**：`requestPort()` 需用户手势，首次授权无法静默完成。之后同浏览器同 origin 授权持久化。
2. **重插后能否自动连取决于浏览器**：Chrome 的串口授权按设备（VID/PID [+ 序列号]）持久化。若重新枚举后 `getPorts()` 仍返回该端口 → 全自动；若返回空 → 降级为"设备已就绪，请点击连接"，点一次即可。**此点必须用真机实测确认**（见验证步骤）。
3. **多台 V5 无法区分**：同型号 VID/PID 相同，只能取第一个，需保留「选口」按钮兜底。
4. **索引漂移**：用户已确认接受。若固件改动导致 monitor 索引顺序变化，恢复出的订阅/曲线会挂到错误变量上；只需在实参表上退订重订一次即可。
5. **冷启动时序**：本次改动把订阅恢复挂在"目录帧到达"之后，天然避开主控程序未就绪导致订阅帧丢失的问题。

## 验证方式

**构建**：`cd frontend && npm run build`（vue-tsc + vite，须通过）。

**浏览器（无需硬件，`http://localhost:5174/`，dev server 用 `npm run dev` 起）**：
1. 进曲线页，选通道 1 → 加 2 条追踪项、x 窗口改 5s、y 轴改手动量程 → 勾"自动连接"。
2. `localStorage['v5.prefs.v1']` 应出现 `chart` 与 `autoConnect:true`。
3. 硬刷新页面 → 曲线页通道配置、追踪项、窗口、量程应全部原样恢复（分图/大图模式也恢复）。
4. 取消勾选"自动连接"后刷新 → 不应尝试连接；勾回。
5. 连续观察 30s：断线重试期间不应出现日志/状态刷屏（诊断日志里同一错误只留一条）。
6. 勾"演示"再取消，确认 demo 切换不会触发重连循环。

**真机（需用户操作，确认第 2 条风险）**：
1. 插 V5、手动「选口」授权一次，连上后确认订阅与曲线正常。
2. 刷新页面 → 应自动连上（验证 L1：设备未拔）。
3. 给 V5 断电再上电 / 重新烧录 → 观察是否自动重连并自动恢复订阅；若否，确认是否降级为"请点击连接"（则属风险 2，需知悉）。
4. 拔线 → 应显示"正在自动重连"；插回 → 应自动连上并恢复订阅。
